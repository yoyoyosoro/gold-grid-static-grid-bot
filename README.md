# StaticGridBot —— 黄金网格 EA（MQL5）

原生 MQL5 编写、只做多的黄金网格智能交易系统（EA），需要在 **Hedging（对冲）账户** 上运行。结构分两块：上方的**底仓体系**和下方的**密网体系**（三个独立区间）。没有持仓止损，风控面板只做推演显示，不参与交易决策。

当前版本：**v4.09**（编译结果 `0 errors, 0 warnings`）

> 这是个人实盘工具，公开仓库只为方便查看和自用。不是投资建议，也不承诺收益。详见文末「风险提示」。

## 二、安装与运行

1. 把 `StaticGridBot v4.09.ex5` 复制到 MT5 数据目录下的 `MQL5\Experts`（`文件 → 打开数据文件夹` 可以直达）。
2. 回到 MT5，在左侧「导航器 → 智能交易系统」上右键刷新，找到 StaticGridBot。
3. 拖到 **XAUUSD** 图表上，在弹窗里勾选「允许算法交易」。
4. 确认工具栏的「算法交易」按钮是绿色。

注意事项：

- 只支持 **Hedging 账户**，Netting 账户不要用。
- 一个专用账户、一个 XAUUSD 图表实例，不要和其他 EA 混挂在同一品种上。
- 最小手数 0.01，仓位按 0.01 递增。
- 需要 MT5 自带的 `Trade\Trade.mqh`、`Canvas\Canvas.mqh`，标准安装即有。
- 换版本时把新文件放进 `MQL5\Experts`，再重新拖到图表即可；旧版本的持仓状态按 Magic 和固定前缀识别，不会因为文件名不同而丢失。

## 三、策略结构

### 1. 上方底仓体系

在设定的最高价以下建立初始底仓（`InpBaseMagic`），并在下跌过程中按 `InpBaseGridPoints` 间距补碎单（`InpBaseGridMagic`）。碎单攒够一批后合并成合并仓（`InpBaseMergedMagic`）。

- `InpPureDenseMode = true` 时只跑下方密网，不建初始底仓。
- `InpCustomBasePrice > 0` 时改为「潜伏狙击点」：价格到达该点位才建底仓。

### 2. 下方密网体系（三个独立区间）

每个区间各自设置：是否启用、顶部、底部、间距、手数、止盈、层数、颜色与线型。

| 区间 | 碎单 Magic | 合并仓 Magic | 默认 |
| --- | ---: | ---: | --- |
| 区间 1 | 2 | 4 | 启用 |
| 区间 2 | 6 | 7 | 关闭 |
| 区间 3 | 8 | 9 | 关闭 |

- 网格距离和止盈都用「报价点数」输入，实际价格距离 = 点数 × `_Point`，随品种报价位数自适应。
- 顶部为 0 时智能跟随；区间重叠时允许各自独立下单；**底部包含、顶部不包含**，中间留一个间距的死区。
- 区间 1 手数填 0 时沿用 `InpMinLot`。
- 关闭某个区间会撤掉它的挂单和横线，已有仓位和在途合并继续管理。
- 每个区间两条原生水平线只作显示，不能拖动改参数。

### 3. 订单身份靠 Magic 区分

九个 Magic 必须非零且互不重复，Comment 仅用于显示。EA 对持仓、挂单、合并、切分、历史排重和退出路径都同时按当前品种和本 EA 的 Magic 过滤，不会动同一账户里其他交易。

## 四、合并与拆分

- 只有碎单（Magic 5、2、6、8）参与合并；初始底仓和合并仓不再合并。
- 碎单数量达到 `InpMergeThreshold` 时，锁定**最早成交的恰好一批**，不要求价格连续。`InpEmergencyLimit` 只作警戒提示，不改变每批数量。
- 合并仓手数 = 本批实际承接的总手数，不设统一止盈。
- 拆分：价格到达某笔碎单的原始止盈时，从合并仓里平掉该笔原手数。例如 `10 × 0.01 + 10 × 0.02` 合成 `0.30` 后，按各自止盈分别平 `0.01` 和 `0.02`。
- 合并是「先平后开」，不是服务器级原子操作，无法消除市场时序带来的差异。
- 合并过程中碎单缺失：EA 自己为合并平掉的按正常退出剔除；被人工或强制平掉的只剔除那一笔、不买回，并推送提醒；成交历史 60 秒仍查不到时也按剔除处理（宁少勿多）。

## 五、主要参数

| 参数 | 默认 | 说明 |
| --- | ---: | --- |
| `InpBaseMagic` | 1 | 初始大底仓 Magic |
| `InpBaseGridMagic` | 5 | 底仓回补碎单 Magic |
| `InpBaseMergedMagic` | 3 | 底仓体系合并仓 Magic |
| `InpDownMagic` / `InpDownMergedMagic` | 2 / 4 | 密网区间 1 碎单 / 合并仓 Magic |
| `InpMinLot` | 0.01 | 上方底仓手数与切分单位 |
| `InpPureDenseMode` | false | 只跑密网，不建初始底仓 |
| `InpCustomBasePrice` | 0 | 到达该点位才建底仓，0 = 直接开启 |
| `InpBaseUpperLimit` | 0 | 上方底仓系统最高价；普通模式必须 > 0 |
| `InpBaseGridPoints` | 1000 | 回补间距（点数） |
| `InpBaseTakeProfit` | 1000 | 回补单止盈（点数） |
| `InpEAExitPrice` | 0 | 完全结算退出价，0 = 不启用 |
| `InpDownEnabled` | true | 启用密网区间 1 |
| `InpDownLot` | 0 | 区间 1 手数，0 = 沿用 `InpMinLot` |
| `InpDownUpperLimit` | 0 | 区间 1 顶部，0 = 智能跟随 |
| `InpDownLowerLimit` | 4000 | 区间 1 底部 |
| `InpDownGridPoints` | 300 | 区间 1 买入间距（点数） |
| `InpDownTakeProfit` | 500 | 区间 1 止盈（点数） |
| `InpMaxGridLevels` | 20 | 区间 1 动态候选层数 |
| `InpOffsetPoints` | 0 | 所有挂单的统一整数偏移 |
| `InpMergeThreshold` | 30 | 每批合并的碎单数量 |
| `InpEmergencyLimit` | 180 | 碎单紧急警戒线 |
| `InpPsyStopOutLevel` | 3000 | 心理防爆仓底线，只用于面板推演 |
| `InpPanelX` / `InpPanelY` | 600 / 20 | 面板偏移 |
| `InpPanelFontSize` | 11 | 面板整体缩放，11 = 标准大小 |

区间 2、3 各有同名的一组参数（`InpDown2*` / `InpDown3*`），默认关闭。

手机上想收到提醒，先装 MT5 手机端并在终端里开启推送，再按需打开 `InpPush*` 开关。

## 六、风控面板

一张 Canvas 绘制的面板，从上到下依次是：标题栏（版本号、收起按钮）、安全灯、四张大字卡片（今日已交易次数 / 当前浮动 / 今日利润 / 本月利润）、风控推演对照表、持仓手数表、隔夜利息。

- 点标题栏任意位置收起或展开；收起后只剩安全灯和今日次数。
- 数据不变不重画，变化时最快 0.5 秒刷新一次。
- 整体大小 = `InpPanelFontSize / 11 × 系统显示比例`，只能等比缩放。150% 显示比例下完整展开约 890 像素高，屏幕放不下就把参数调到 9。
- 美分账户（币种含 `USC` / `CENT`）金额自动除以 100，按美元显示。
- 风控推演只做「现在多少 / 配置打满多少」的估算，不拦截下单。

**「今日」按北京时间早上 6 点换日**，今日次数、今日/本月利润、每日小结推送都按这个口径。交易 1 次 = 一笔平仓成交（服务器止盈、合并仓拆分、部分平仓各算一次；EA 为合并关掉的碎单不算）。

## 七、状态保存与恢复

- 状态存在 MT5 全局变量里，按账户、品种、Magic 隔离；每次发交易请求前和每个 tick 结束都会强制落盘。
- 启动后等服务器连接 3 秒才读状态、核对持仓、开始交易。
- 底仓记录丢失时，有初始底仓就按其开仓价恢复；只有遗留的碎单或合并仓时暂停建底仓、推送提醒，等人工处理。
- 断网、重启或跳空后，按已保存的水位逐层补切，用 30 天历史排重，单个 tick 最多补 20 个动作。
- 初始化会撤销旧挂单，按当前参数重新铺网格。

> 面板显示的数字、参数文件、旧版本遗留状态都属于运行期数据，不要在 EA 运行中手工删除全局变量，否则会丢失合并/退出进度。

**完全结算退出**：设置 `InpEAExitPrice` 后，价格到达该点位会依次执行「冻结新交易 → 删除挂单 → 平掉持仓 → 确认清零 → 删除状态并卸载」。中途失败会保持「退出中」并在下个 tick 重试；超过 5 分钟没清零会推送提醒。挂载时如果现价已经越过一个从未生效过的退出价，会先弹窗确认，选「否」则不交易并直接卸载。

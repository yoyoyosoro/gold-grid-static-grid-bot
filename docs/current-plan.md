# 当前计划

最后更新：2026-09-21

## 目标与阶段

从已验收的 v4.04 新建 `StaticGridBot v4.05`，将下方密网扩展为三个独立区间，升级风控并绘制区间顶底横线。

v4.05 实现与本地编译已完成，隔离 MT5 脚本测试 27,619 项断言通过。交易时序验收尚未完成：隔离策略测试器因未配置账户拒绝启动。旧版本全部保留，未部署或替换当前终端 EA。

实现覆盖下述 1 至 5 项；第 6 项已完成编译、计算/状态恢复和横线对象属性验证，成交、旧仓接管及图表视觉验收仍待完成。详细证据与限制见 `docs/progress.md`。

## 已确认的规则

- 三个区间分别配置：启用、顶部、底部、网格间距、手数、止盈距离、动态挂单层数；各自支持顶部设 0 智能跟随。
- 三个区间和上方底仓继续使用统一 `InpOffsetPoints`，不新增区间独立偏移。
- 按候选挂单目标价判断区间，保留现有下限包含、上限不包含及 `0.001` 容差规则；保留一个网格间距的挂单死区、5 秒同步和两层清理缓冲。
- 不增加现价进入区间才启动的条件；动态层数沿用现有候选层数含义，不承诺实际挂单笔数恰好等于输入层数。
- 重叠区间独立下单，同价订单互不排重；合并不跨区间，拆分按各笔原始 TP 和实际手数执行；合并阈值全局共用。
- 参数修改作用于后续新挂单；已有散单保留原 TP，已有合并仓保留原阶梯和手数并继续管理。
- 关闭区间停止新挂单、撤销所属未成交挂单、移除所属横线；已有持仓和在途合并流程继续管理。
- 保留上方底仓系统与全局总目标退出；区间顶部本身不触发全局平仓。
- 旧密网持仓及可恢复状态归区间 1；旧挂单沿用初始化撤销后重新同步的方式，不承诺保留票号和原挂单价格。
- 每区间使用两条原生水平线，顶底共用该区间颜色、粗细和线型；每区间独立设置显示开关。横线只作标记，不通过拖动修改交易参数。

## 源码核对发现

- `ManageGridOrders()` 当前只有一个密网来源身份，需完整扩展挂单、清理、排重和持仓识别。
- `DynamicTPUpdater()` 当前按最新输入重算散单 TP，必须改造密网持仓路径，才能满足旧仓保留原 TP。
- `SliceOneManagedUnit()` 当前从整个 EA 的非合并持仓挑选减仓对象；`CheckHistoryForExit()` 也查询所有受管 Magic。必须隔离，不能只增加三个挂单循环。
- 密网切分水位、合并计划和活跃阶梯存储在终端全局变量中；区间 1 必须保持旧状态可寻址，区间 2、3 分别隔离。
- 风险满载场景与第 7 项均依赖单区间参数，需同步改造。

## 施工顺序

### 1. 参数、身份与兼容入口

- 新建 v4.05；区间 1 默认启用，区间 2、3 默认关闭。以小型配置结构统一读取三个区间，保持现有单文件架构。
- 区间 1 保留旧密网来源及合并 Magic，默认 2、4；区间 2、3 分别增加唯一来源及合并 Magic，默认建议 6、7 和 8、9；底仓的 1、5、3 保持原职责。
- 校验全部受管 Magic 非零且互不重复；启用区间校验顶底、手数、间距、TP 和层数；关闭区间不因尚未配置顶底而阻止启动。
- 尽量保留区间 1 的旧输入名称。`InpMinLot` 原先兼任底仓和密网手数，分离后明确旧值到区间 1 手数的映射，不宣称旧参数文件自动无损迁移。
- 保留区间 1 旧状态命名空间；新增区间状态不能因开关变化而失去旧仓身份。

验收：仅启用区间 1 且参数一致时，候选挂单价格与数量和 v4.04 对照一致；错误参数在任何撤单、下单前拒绝启动。

### 2. 独立交易、合并和恢复

- 挂单生成、越界清理、持仓排重、合并暂停、历史排重、切分水位按区间隔离。
- 反弹补切只选择本体系持仓；上方底仓继续执行自身规则，不因扩展受管 Magic 而切掉其他区间仓位。
- 合并仍按最早成交的严格笔数选批次，支持同区间混合手数；保存实际手数和原 TP，保留服务器 TP 并发退出保护。
- 修改间距或统一偏移时识别网格坐标变化，不把旧层级整数直接套到新网格追补减仓；既有合并阶梯保持不变。
- 全局退出继续按冻结、撤单、平仓、确认清零、卸载顺序执行，覆盖已关闭区间的遗留仓。

验收：同价重叠、异间距、区间空白、开关切换均不串单；历史排重及合并拆分不跨区间；重启不重复补切。

### 3. 旧仓接管与参数修改保护

- 启动先识别区间 1 的旧散单、在途合并和已有阶梯，再进入管理；不重写旧持仓 Magic。
- 旧散单已有 TP 为接管依据；新散单使用创建时的目标 TP。必要的目标保存按持仓标识绑定，支持重启；新输入不得重算旧仓目标。
- 旧合并仓沿用真实阶梯状态；缺少原 TP 或阶梯时明确诊断，不用最新参数伪造原始管理规则。
- 是否允许新挂单与已有仓位管理分离；关闭区间时在途合并仍按真实进度恢复，不能丢失已关闭碎单对应的承接责任。

验收：带旧散单、混合手数合并仓和在途合并状态启动；修改手数、TP、间距后旧目标及阶梯不变，新挂单使用新参数；关闭后重启仍能管理旧仓。

### 4. 多区间风控

- 当前持仓风险基于全部受管持仓的实际手数和成本，包含关闭区间的遗留仓。
- 配置满载按各启用区间的真实网格档位枚举并乘以各自手数，重叠分别计数，空白不补网格；继续纳入上方底仓场景。
- 交易与推演共用区间资格、价格对齐和统一偏移规则，避免端点多算或少算一层。
- “跌到底部”采用启用区间最低底部。全部区间关闭时，依赖区间底部和密度的项目显示不适用；实际持仓风险和统计继续有效。
- 第 7 项固定各区间手数、边界、统一偏移及上方底仓配置，仅按共同系数缩放启用区间的间距；取整为合法报价点后重新枚举风险，并显示三个对应间距。
- 第 7 项按离散合法网格求解，不能直接套旧连续公式或未经证明的单调二分。按心理防线处权益与强平阈值判断可行性，结果必须复算；未完成求解时不显示伪造的最密数值。
- 配置满载与实际持仓为两个明确场景，分别计算，不能直接相加造成重复计数；显示不能暗示关闭区间的旧仓风险已经消失。
- 保留免保证金有效、真实 API 失败时不可用、美分账户换算及原持仓分类统计。

验收：以人工可核算的小网格对照档位数、总手数、加权成本；覆盖异手数、异间距、重叠、空白、统一偏移、全部关闭、遗留仓和零保证金。

### 5. 区间横线

- 使用 `OBJ_HLINE`；对象名和标签包含区间及顶底身份，不覆盖用户手工线。
- 显示条件为区间启用且画线开关开启；顶部设 0 时画解析后的智能顶部，并随其变化更新。
- 参数变化更新位置和样式；关闭区间或卸载 EA 只清理本 EA 对象。
- 采用 MT5 原生线型和粗细能力；实施时核实宽线与虚线组合的实际渲染限制，不能承诺平台不支持的效果。

验收：各区间独立显隐，关闭无残留；同价线允许视觉重合，可通过对象名识别；拖动不改变交易边界。

### 6. 编译、场景验证与交付

- MetaEditor 编译 v4.05 并读取日志，要求 `0 errors, 0 warnings`。
- 先验证价格枚举、身份隔离、风险聚合与状态兼容，再在隔离测试环境验证成交、合并、拆分、参数修改和重启时序。
- 重点回归：单区间挂单等价、三区间同价订单并存、旧仓接管、关闭后管理、合并中断恢复和总目标退出。
- 检查实际 MT5 横线和面板显示；编译、静态检查不能代替终端行为验收。不能执行的验证明确保留为未验证。
- 交付匹配的 `.mq5`、`.ex5` 和编译日志，按已验证结果更新进度，不自动替换实盘版本。

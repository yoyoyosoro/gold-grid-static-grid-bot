# StaticGridBot 项目记忆

最后核对日期：2026-11-12

## 项目定位

StaticGridBot 是原生 MQL5、只做多、仅支持 Hedging 账户的黄金网格 EA，包含上方底仓体系与下方密网体系（三个独立区间）。没有持仓 SL；风控面板只作推演显示，不参与交易决策，也不构成收益或安全保证。

## 版本、路径与验证

- **当前版本**：`StaticGridBot v4.08`，用户 2026-11-12 验收。实盘环境为 Exness `XAUUSDc` 美分账户，用户边运行边升级。
- 工作区保留 v3.98 至 v4.08 各版 `.mq5` / `.ex5` / 编译日志，作为存档；新版本复制到 MT5 `MQL5\Experts`，由用户自己切换图表。
- **编译**：MetaEditor 命令行需带 `/include:` 指向 `%APPDATA%\MetaQuotes\Terminal\D0E8209F77C8CF37AD8BF550E51FF075\MQL5`。工作区路径含中文，直接传会被转成乱码，可先复制到英文路径再编译。
- **回归测试**：`tests/v408_tests.mq5` 直接包含生产源码，复制到 `tests/runtime`（无账户隔离 MT5，`/portable`）用 `isolated-test-v408.ini` 运行，结果写 `MQL5\Files\v408-results.txt`，不发交易请求。新版本照此复制一份测试脚本。
- **验证方式**：每版做编译与隔离回归，再由用户实盘观察。用户不需要基础成交流程测试。
- 本机 Windows 显示比例为 150%（144 DPI），会影响面板像素尺寸。

## 部署边界

- 专用账号、单一 XAUUSD 图表实例，不与其他 EA 混挂。
- 所有持仓、挂单、合并、切分、历史排重和退出路径都同时筛选当前 `_Symbol` 和本 EA Magic。
- 只支持最小 `0.01` 手、按 `0.01` 递增。

## 订单身份（九个 Magic，必须非零且互不重复）

| 用途 | 参数 | 默认 |
| --- | --- | ---: |
| 初始大底仓 | `InpBaseMagic` | 1 |
| 底仓回补碎单 | `InpBaseGridMagic` | 5 |
| 底仓体系合并仓 | `InpBaseMergedMagic` | 3 |
| 密网区间 1 碎单 / 合并仓 | `InpDownMagic` / `InpDownMergedMagic` | 2 / 4 |
| 密网区间 2 碎单 / 合并仓 | — | 6 / 7 |
| 密网区间 3 碎单 / 合并仓 | — | 8 / 9 |

职责以 Magic 为准，Comment 只作显示。状态命名空间沿用旧版（v3.98 / v4.00 / v4.05 前缀），不要改名，否则升级时会丢失在场仓位的状态。

## 参数与网格规则

- `InpBaseUpperLimit`：上方底仓最高价，普通模式必须大于 0；`InpPureDenseMode = true` 时可为 0，此时每个启用的密网区间必须填明确顶部，并保留场内旧底仓的原止盈。
- `InpEAExitPrice`：独立的完全结算退出价，0 表示不启用。用户每次手动配置，旧参数文件默认 0 的问题不处理。
- 网格和 TP 用点数输入，价格距离 = 点数 × `_Point`，输出按 `_Digits`。
- 三个密网区间各自独立：启用、顶部/底部、间距、手数、TP、层数；统一 `InpOffsetPoints`。区间重叠时允许独立订单；底部包含、顶部不包含，保留一个间距的死区；顶部为 0 时智能跟随。区间 1 手数为 0 时沿用 `InpMinLot`。
- 关闭区间：撤挂单和横线；已有仓位和在途合并继续管理。
- 改参数不会重算旧密网单的 TP 和已有合并阶梯。底仓回补单改“回补止盈”后，已成交单也按新参数改 TP。两套体系这样区别对待是有意设计。
- 每个区间两条原生 `OBJ_HLINE`，只作显示，不能拖动来改参数。实线 1 至 5 像素，虚线固定 1 像素。

## 合并与拆分

- 合并来源只有碎单（5、2、6、8）；初始底仓和合并仓不再参与合并。
- 碎单数量达到 `InpMergeThreshold` 时，只锁定最早成交的恰好一批，价格不要求连续；`InpEmergencyLimit` 只作警戒。
- 锁定时持久保存每笔碎单的持仓标识、实际手数、原始 TP。合并仓手数等于本批实际承接的总手数，不设统一 TP。
- 拆分：价格到达某笔原始 TP 时，从合并仓平掉该笔原手数。例如 `10 × 0.01 + 10 × 0.02` 会合成 `0.30`，再按各自 TP 分别平 `0.01` 或 `0.02`。
- 合并中碎单缺失的处理：原始 TP 或 EA 自己的防倒挂、补切平掉的，按正常退出剔除；被人工或强平平掉的，只剔除那一笔、不买回，并推送。EA 为合并而平的才计入。成交历史 60 秒仍查不到时按剔除处理，宁少勿多。
- 合并建仓回执失败时保持“等待确认”，15 秒内找到成交就绑定，找不到才重发。
- 合并是先平后开，不是服务器级原子操作。

## 状态、启动与退出

- 状态存在 MT5 全局变量里，按账户、品种、Magic 隔离。全部写入经过 `GVSet/GVDel/GVDeleteAll`，在发交易请求前和每个 tick 结束时强制落盘；每天读一遍，防止 MT5 自动删除 4 周没读过的记录。
- 启动：连上服务器 3 秒后才读状态、核对持仓、开始交易。底仓记录丢失时，有 Magic 1 就按其开仓价恢复；只有 5/3 遗留仓时暂停建底仓、推送提醒，等人工处理。
- 断网、重启或跳空后按已保存水位逐层补切，30 天历史用于排重，单 tick 最多 20 个补切动作。
- 初始化会撤销旧挂单，按新配置重铺。
- 挂单只认买入限价单。服务器执行止盈时会临时出现同 Magic 的卖出市价单，不去动它。
- 挂单受阻（只允许平仓 10044、休市、挂单数达上限）时，本轮停止挂单并暂停 60 秒；启动时估算所需挂单数，超过 `ACCOUNT_LIMIT_ORDERS` 就提醒。
- 完全结算退出状态机：冻结新交易 → 删挂单 → 平持仓 → 确认清零 → 删除状态并卸载。失败就保持“退出中”，下个 tick 重试，超过 5 分钟未清零推送提醒。挂载时如果现价已越过一个从未生效过的退出价，先弹窗确认；选“否”不交易，直接卸载。

## 手机推送

总开关加 7 个分组：完全退出、安全灯、合并与阶梯异常、连续失败、系统状态默认开；每批合并完成、每日小结默认关。同类消息有冷却，遵守 MT5 每秒 2 条、每分钟 10 条的限制，发送失败 30 秒后重试。安全灯状态持续 60 秒才推送，启动后第一个稳定状态只作基线。

## 风控面板（v4.08 方案 B，用户验收）

- 一张 Canvas 位图，只用纯色、圆角、1 像素线和文字绘制。从上到下：标题栏（纯密网标签、版本号、收起按钮），安全灯，四张大字卡片（上排“今日已交易 n 次 / 当前浮动”，下排“今日利润 / 本月利润”），风控推演“当前持仓 / 配置满载”对照表，持仓单量手数表，隔夜利息两行。不用编号。
- 点标题栏任意位置一键收起或展开；收起后只剩安全灯和今日次数，0.35 秒内的重复点击忽略。
- 数据没变就不重画，变化时最快 0.5 秒刷新一次；只在尺寸变化时才 `Resize`。
- 大小：`InpPanelFontSize / 11 × Windows 显示比例`，只能等比缩放。150% 显示比例下完整展开约 890 像素高，放不下时把参数调到 9。
- 金额统一经 `DisplayRate` 换算：美分账户（币种含 USC / CENT）除以 100，按美元显示。
- **“今日”= 北京时间早上 6 点换日**。夏令时正好是开盘，冬令时落在每日休市内。今日次数、今日/本月利润、每日小结推送都用这个口径。
- **交易 1 次 = 一笔平仓成交**：服务器止盈、合并仓拆分、部分平仓各算一次。EA 为合并关掉的碎单不算，按交易日计数后扣除。利润含隔夜利息、手续费。
- 风险缓存是原子快照，计算失败时风控推演和安全灯整体显示不可用。经纪商合法返回的零保证金是有效值，显示“免保证金”，不误报追保。
- 参考手数按经纪商最小值、最大值、步长取值。持仓统计不包含挂单；实际风险包含已关闭区间的遗留仓。配置满载按真实离散档位累加，重叠区间分别计入。最密间距按共同系数缩放各区间，逐个组合验证，未算完时显示“计算中”。

## 维护边界

- 保留 5 秒挂单同步节流、两层删除缓冲、一个间距的重新挂单死区。
- 未经要求，不新增动态仓位倍率、净值复投、ATR 间距、CSV 日志或模块拆分。

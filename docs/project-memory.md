# StaticGridBot 项目记忆

最后核对日期：2026-11-12

## 项目定位

StaticGridBot 是原生 MQL5、只做多、仅支持 Hedging 账户的黄金网格 EA。它包含上方底仓体系与下方密网体系；没有持仓 SL，风控面板只作 UI 推演，不参与自动交易决策，也不构成收益或安全保证。

## 部署边界

- EA 用于专用账号，不与其他 EA 混挂；正式运行目标是单一 XAUUSD 图表实例。
- 所有持仓、挂单、合并、切分、历史排重和退出路径同时筛选当前 `_Symbol` 与本 EA Magic。
- 项目支持最小 `0.01` 手、以 `0.01` 递增；不承担 `0.001` 手规格。

## v4.05 已确认设计

- 将下方密网扩展为三个独立区间，重叠允许独立订单；每区间启用、顶部/底部、间距、手数、TP、层数独立，统一 `InpOffsetPoints`。
- 挂单按目标价格资格，保留底部包含、顶部减 0.001 后不包含和一个间距死区；顶部 0 沿用智能跟随。
- 关闭区间撤挂单和横线，已有仓位和在途合并继续管理；旧密网 TP 和已有合并阶梯不随新参数改写。
- 旧密网归区间 1，Magic 和状态命名空间保持兼容；区间 1 手数 0 表示沿用 `InpMinLot`。首次升级保留原间距/偏移以恢复旧水位，旧挂单仍初始化重铺。
- 区间 2 碎单/合并 Magic 默认 6/7，区间 3 为 8/9；全部九个 Magic 唯一。合并、切分和历史排重只在所属体系内执行。
- 实际风险含关闭区间遗留仓；配置满载按真实离散档位累加，重叠分别计入、空白不补；底部用启用区间最低底部。最密间距固定手数、共同缩放各间距并验证每个离散组合。
- 每区间两条原生 OBJ_HLINE，独立显示开关/颜色/线宽/线型，不通过拖动改交易参数；停用时移除。MT5 虚线固定 1 像素，实线可用 1 至 5 像素。
- 上方底仓最高价与 EA 完全结算退出价分离；区域顶部不触发全平；缺少旧 TP 或原阶梯时不虚构恢复。

## v4.07 已确认设计（2026-11-12）

- **启动核对**：MT5 开机时 EA 常先于账户同步加载、看不到持仓。EA 等连上服务器 3 秒后才读状态、核对持仓、开始交易。
- **防重复建底仓**：底仓起始价记录缺失时先看场内。有 Magic 1 初始底仓就按其开仓价恢复记录；只有 Magic 5/3 遗留仓时暂停建底仓并推送，等人工确认。
- **状态保活与落盘**：MT5 全局变量 4 周未读取会被自动删除，EA 每天把本 EA 状态读一遍（原始止盈记录只刷新在场持仓）。所有状态写入经 `GVSet/GVDel/GVDeleteAll`，在发交易请求前和每个 tick 结束时强制落盘。
- **合并建仓回执失败**：保持“已发送、等待确认”，15 秒内找到成交就绑定，找不到才重发，避免网络卡顿时开两笔。
- **合并中碎单缺失（用户 2026-11-12 拍板，取代 v4.00“未知退出取消整批”）**：原始 TP 退出、或 EA 自己的防倒挂/补切平仓，按正常退出剔除；被人工、强平等其他方式平掉的只剔除那一笔、不买回并推送，其余碎单照常合并；EA 为合并发出的平仓即使回执不明，只要历史确认是本 EA 平的就计入。历史 60 秒仍查不到时按剔除处理，宁少勿多。
- **退出价误填保护**：现价已越过退出价、此前不在退出中、且这个退出价从没在现价下方生效过时，弹窗确认；选“否”不做任何交易并卸载 EA。同一退出价此前已生效（关机期间行情真的越过）则照常直接退出。
- **纯密网且底仓最高价为 0**：保留场内旧底仓的原止盈，不改成 0。
- **挂单只认买入限价单**：服务器执行止盈时会临时出现同 Magic 的卖出市价单，EA 不再去改止盈、删除或排重它们（实盘日志一个月约 120 次 invalid request 来自这里）。
- **挂单受阻**：经纪商只允许平仓（每日结算时段 retcode 10044，实盘一个月约 440 次）、休市或挂单数达上限时，本轮停止挂单并暂停 60 秒。启动时按配置估算所需挂单数，超过 `ACCOUNT_LIMIT_ORDERS` 就提醒。
- **手机推送**：总开关加 7 个分组开关（完全退出、安全灯、合并与阶梯异常、连续失败、系统状态默认开；每批合并完成、每日收益小结默认关）。同类消息有冷却，遵守 MT5 每秒 2 条、每分钟 10 条的限制，发送失败（多为断网）30 秒后重试。安全灯状态持续 60 秒才推送，启动后第一个稳定状态只作基线。连续失败计数不含仓位已平、冻结、休市、只允许平仓、本机关自动交易、挂单达上限。
- **面板 ⑩⑪**：今日/本月已实现收益（含隔夜利息、手续费）、当前浮动、持仓累计隔夜利息、本月已结算隔夜利息。“今日”按经纪商服务器时间划分。
- 用户决定：完全结算退出价每次手动配置，旧参数文件导致默认 0 不启用退出的问题不改。
- 用户决定（2026-11-12）：止盈规则两套体系有意不同。密网旧单保留原止盈；底仓回补单在改“回补止盈”参数后，已成交单也按新参数改止盈。这是设计，不是缺陷。

## v4.02 订单身份

| 用途 | 参数 | 默认 Magic |
| --- | --- | ---: |
| 初始大底仓 | `InpBaseMagic` | 1 |
| 底仓回补碎单 | `InpBaseGridMagic` | 5 |
| 下方密网碎单 | `InpDownMagic` | 2 |
| 底仓体系合并仓 | `InpBaseMergedMagic` | 3 |
| 密网体系合并仓 | `InpDownMergedMagic` | 4 |

新仓职责以 Magic 为准，Comment 只作显示辅助。五个 Magic 必须非零且互不重复。用户确认升级时当前没有初始底仓，因此不需要迁移场内旧底仓身份。

## 合并批次与拆分规则

- 合并来源只允许 Magic 5 的底仓回补碎单或 Magic 2 的密网碎单；初始底仓和已有合并仓不参与再次合并。
- 触发条件按持仓笔数计算。达到 `InpMergeThreshold` 后，只锁定最早成交的恰好一批，多余碎单等待下一批；价格层级不要求连续。
- 碎单身份不再使用当前 `InpMinLot` 判断。改变后续下单手数不会把旧手数碎单排除在外。
- 关闭前持久保存每笔碎单的持仓标识、实际手数和原始 TP。新合并仓手数等于本批实际由 EA 承接的总手数。
- 每个拆分档位保存自己的实际手数；价格达到该笔原始 TP 时，只从所属合并仓平掉该笔原手数。因而 `10 × 0.01 + 10 × 0.02` 会形成 `0.30` 合并仓，并按各自 TP 分别平 `0.01` 或 `0.02`。
- 若逐笔关闭期间某笔先由服务器原始 TP 完整退出，该笔从本批合并体积和拆分阶梯剔除，其余碎单继续合并。v4.07 起，其他方式退出也只剔除那一笔，不再取消整批（见 v4.07 设计）。
- 新合并仓不设统一 TP，并排除通用 TP 更新和全局补切；状态绑定到该合并仓自己的 `POSITION_IDENTIFIER`。
- `InpEmergencyLimit` 仅作兼容和人工警戒，不改变严格批次数量。

## 参数和网格规则

- `InpBaseUpperLimit` 是上方底仓系统最高价；普通模式必须大于 0，`InpPureDenseMode = true` 时允许为 0。它继续用于初始底仓目标、上方底仓档位和未指定密网顶部时的智能顶部。
- 仅运行密网且 `InpBaseUpperLimit = 0` 时，每个启用的密网区间必须填写大于 0 的明确顶部，不能使用顶部 0 的智能跟随。
- `InpEAExitPrice` 是独立的 EA 完全结算退出价；大于 0 且现价达到该价时触发全 EA 清仓，设为 0 表示不启用价格触发退出，不因该值为 0 拒绝启动。
- 参数只校验常见错误：上下限、点数、层数、阈值、最小手数以及五个 Magic。
- 网格和 TP 保留点数输入，实际价格距离为 `输入点数 × _Point`；价格输出按 `_Digits`。
- `InpPureDenseMode` 是明确开关；`true` 时不建立初始大底仓。
- `InpDownLowerLimit` 是网格铺设下限，只过滤目标价低于下限的密网候选挂单。它不限制初始底仓、底仓回补和底仓体系合并，也不撤销先前合法挂单。

## v4.01 风控面板规则

- 风险缓存是成组提交的原子快照；保证金或盈亏计算任一失败，1-7 项和安全灯均显示不可用。
- 参考手数按经纪商品种最小值、最大值和步长选取，不固定假定为 1 手。
- 第 8 项统计当前持仓记录数，第 9 项统计实际手数；不统计挂单。
- v4.02 中底仓类别为 Magic 1、5、3，密网为 Magic 2，密网合并为 Magic 4。

## v4.04 风控面板规则

- 当前 `XAUUSDc` 经纪商在无限/免保证金模式下，`OrderCalcMargin()` 成功返回 `0` 是有效结果；不能再用“保证金必须大于 0”判断计算失败。
- 风控缓存接受 API 成功、有限且非负的保证金值；API 失败、非有限值或负值仍使 1-7 项和安全灯显示不可用。
- 有效零保证金模式下，①②③显示 `$0.00` 与“免保证金”；④⑤⑥⑦继续按有效盈亏基准推演，安全灯不再因零保证金误报追保。
- 第 8 项细分底仓单量、网格单量、网格合并单量和总量；第 9 项细分底仓手数、网格手数、网格合并手数和总手数；两项均不统计挂单。
- 报价点数仍按输入点数乘 `_Point`，输出价格按 `_Digits`，随平台报价精度自适应。

## 运行状态与重启恢复

- 状态按账户、品种和 Magic 隔离，保存起始价、上方/密网切分水位、退出中标志以及每个合并批次的阶梯。
- v4.02 为兼容已存在的密网合并仓状态，主状态命名空间继续沿用 v4.00 的四个原 Magic；新的来源 Magic 会写入具体合并计划键，不会与密网计划混用。
- 启动时核对起始价状态和实际持仓；不存在的旧状态自动清理，可识别的实际原始底仓价用于刷新状态。
- 断网、重启或跳空后按已保存水位逐层追补；30 天历史用于排重，不用现价覆盖旧水位。单 tick 最多提交 20 个补切动作。

## EA 完全结算退出状态机

仅当 `InpEAExitPrice > 0` 且现价达到该价格，或此前已经持久化为“退出中”时，才进入以下状态机：

```text
冻结新交易
  → 删除本 EA 挂单
  → 平掉本 EA 持仓
  → 扫描确认挂单和持仓均为 0
  → 删除状态并卸载 EA
```

任一请求失败时保持“退出中”，后续 tick 继续扫描和重试。v4.07 起，挂载时若退出价疑似误填会先弹窗确认；退出超过 5 分钟未清零会推送提醒。
